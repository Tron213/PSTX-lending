# ПАСТУХ: Apache + PHP

Сайт работает через существующий Apache.
Node.js, npm, сборка и база SQL не нужны.

## Требования

- Apache с обработчиком PHP 7.4 или новее.
- Рекомендуется поддерживаемая версия PHP 8.
- Папка проекта — DocumentRoot сайта.
- PHP должен иметь право создать .pastukh.
- Для размещения в интернете используйте HTTPS.

PHP — обязательное условие для админ-панели.
Если Apache обслуживал только HTML, проверьте,
что обработчик PHP установлен и включён.
Не публикуйте PHP как простой текст.

## Открытие в VS Code

Распакуйте ZIP и откройте папку проекта
через «Файл → Открыть папку».
Все файлы готовы к редактированию.
Сборка и установка npm-пакетов не нужны.

## Запуск на существующем Apache

1. Сохраните копию старых файлов сайта.
2. Скопируйте содержимое этой папки
   в корень вашего сайта на Apache.
3. Не удаляйте существующую .pastukh:
   в ней хранятся новости и настройки.
4. Убедитесь, что Apache обрабатывает PHP.
5. Обновите страницу с очисткой кэша.

Копируйте и скрытые файлы .htaccess
и .user.ini. Адрес сайта остаётся прежним.
Новости: /news.html.
Админ-панель: /admin/index.php.

Сайт рассчитан на корень домена.
Если положить его в подпапку /pastukh,
абсолютные ссылки будут вести не туда.
Настройте DocumentRoot на папку проекта
или перенесите файлы в текущий корень.
RewriteRule и mod_rewrite не требуются.

## Локальная проверка

При наличии PHP в PATH откройте терминал
VS Code в папке проекта и выполните:

```sh
php -S localhost:8000
```

Откройте http://localhost:8000 в браузере.
Встроенный сервер PHP подходит для локальной
проверки. Для размещения используйте Apache.
Расширение Live Server для входа и новостей
не подходит: оно не выполняет PHP.

На Windows также можно использовать Apache
и PHP из уже установленного XAMPP/OpenServer.
Папку проекта укажите как корень сайта.

## Первый вход

1. Откройте /admin/login.php на своём сайте.
2. PHP создаст каталог .pastukh.
3. На сервере откройте .pastukh/setup-key.php
   через SSH или файловый менеджер хостинга.
4. Скопируйте значение token из файла.
5. Вставьте ключ в форму первоначальной
   настройки, задайте логин и пароль.

Логин: 3–64 символа, латиница, цифры,
точка, дефис или подчёркивание.
Пароль: от 10 до 128 байт.
После создания администратора ключ удаляется,
а первоначальная настройка отключается.
Общего пароля в исходниках нет.

В дальнейшем входите по своему логину
и паролю. ChatGPT для этого не нужен.

Если нет прав записи, администратор сервера
должен создать .pastukh и дать владельцу
процесса PHP права записи в этот каталог.
Не выставляйте права 777 на весь проект.

## Управление

- «Добавить новость»: текст, фото и видео.
- «Редактировать»: изменить текст и вложения.
- «Удалить»: убрать публикацию из ленты.
- «Настройки входа»: сменить логин и пароль.
- «Выйти»: завершить текущий сеанс.

До 6 вложений на новость.
Фото — до 10 МБ, видео — до 50 МБ.
Рекомендуемый видеоформат — MP4.
Лимит тела запроса Apache/PHP должен
позволять загрузки размером до 50 МБ.

## Данные

.pastukh содержит новости, вложения,
хеш пароля и счётчики попыток входа.
Не удаляйте и не публикуйте этот каталог.
Сеансы хранятся средствами PHP на сервере.
Для резервной копии сохраните .pastukh.

При обновлении заменяйте исходники сайта,
сохраняя существующий каталог .pastukh.

Это новая PHP-версия серверной части.
Данные из Node.js-папки data или облачного
хранилища автоматически не импортируются.
Существующая папка data не удаляется.
Старые исходники Node.js сохранены для справки.
Они больше не используются при запуске.
Старый server/index.js запускает PHP-сайт.

## Структура

- index.html — главная страница.
- news.html — отдельная вкладка новостей.
- styles.css — общие стили.
- news.css — стили новостей и панели.
- admin/ — PHP-страницы администратора.
- private/ — обработчики и шаблоны.
- api.php — запросы браузера к серверу.
- assets/ — логотип и материалы проекта.

Редактируйте файлы в корне проекта.
Папка public — архив прежней версии.
Apache не должен обслуживать её как сайт.
DocumentRoot укажите на корень проекта.
Редактор VS Code запускает ту же PHP-версию.
Для локального запуска PHP нужен в PATH.
Через npm start можно также задать PHP_BINARY.

## Содержание и черновики

В админке появился раздел «Проект и материалы»:
паспорт, команда, прототип, испытания, пилот,
материалы, ответы и готовность возможностей.
Заполните раздел, проверьте предпросмотр,
выберите «Опубликовано» и сохраните.
К разделу можно добавить до 6 фото или видео.
Черновые вложения закрыты от гостевого доступа.
Все разделы изначально являются черновиками.
Неизвестные сведения не подставляются в сайт.
Для снятия публикации верните статус «Черновик».
Гостевой API не отдаёт черновые разделы.

Новости имеют статусы и три типа записи:
новость, результат испытания и план испытания.
Незаполненную запись сохраняйте черновиком.
Публичная страница показывает опубликованное.
Вложения черновиков доступны только админу.
Старые новости без статуса остаются видимыми.

## Ознакомительный сайт и пример приложения

Учёт животных будет отдельным приложением.
Сайт знакомит с проектом, публикует материалы,
новости и результаты испытаний.
Админка управляет содержанием сайта.

В разделе аналитики показан тестовый реестр:
выберите условного телёнка, посмотрите историю
и добавьте готовое демонстрационное измерение.
Кнопка сброса возвращает исходный пример.
Все изменения существуют только в памяти
текущей страницы. Обновление страницы сбрасывает
демонстрацию. Подключений и сохранения данных нет.

Рабочие API учёта и экспорта отключены.
Прежние данные .pastukh остаются нетронутыми.
Материалы сайта хранятся в project-content.php
в существующем каталоге .pastukh.

## Проверки разработки

При наличии Node.js и PHP:

```sh
npm run check
npm test
```

PHP_BINARY позволяет указать полный путь к PHP.
Интеграционные тесты создают временную копию.
Они не открывают рабочую папку .pastukh.

## Если забыли пароль

Нужен доступ к файлам сервера.
Сохраните резервную копию .pastukh.
Удалите только .pastukh/account.php.
Откройте /admin/login.php и повторите
первоначальную настройку с новым ключом.
Новости и вложения сохранятся.

## Проверка PHP

На сервере с PHP CLI:

```sh
php -v
php -l api.php
```

Если файл PHP скачивается или отображается
как исходный текст, сначала настройте PHP
в Apache. Не используйте сайт в таком виде.
